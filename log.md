## 3. Decisions taken where the docs were silent or inconsistent

| # | Topic | Decision | Why |
|---|---|---|---|
| D-01 | DB enums | `TEXT` + `CHECK` constraints instead of native PG enums | Forward-only migrations: adding a value needs no `ALTER TYPE` |
| D-02 | Case-insensitive email | Unique index on `lower(email)` instead of `citext` | Avoids an extension; same guarantee |
| D-03 | Sync vs async | Sync SQLAlchemy + psycopg 3 behind FastAPI's threadpool | Worker is subprocess/IO bound; the API is stateless so it scales horizontally by replicas |
| D-04 | Multiple workers | Monitoring loop is leader-elected with a long-held `pg_try_advisory_lock`; jobs and notification deliveries use `SKIP LOCKED` | Any number of worker replicas without double-evaluating rules or changing the Δ_eval cadence |
| D-05 | Notification delivery | Outbox pattern: `notification_delivery` rows written `pending` in the alert transaction, sent by a delivery loop with retries (3) | Evaluation stays fast; deliveries survive restarts |
| D-06 | Delivery status names | `pending, delivered, failed, suppressed` (API_SPEC uses `delivered`; DATA_MODEL said `sent`) | API_SPEC is the newer contract (2026-10-24 edit) |
| D-07 | Inventory | Native lockfile parsers (package-lock v1–v3, requirements*.txt, Pipfile.lock, poetry.lock, uv.lock) feed OSV/registry; Trivy's inventory is merged in | OSV and registry keep working when Trivy fails (NFR-REL-02) |
| D-08 | Outdated/deprecation checks | Direct dependencies only; npm uses the small `/<pkg>/latest` document | Avoids thousands of registry calls and multi-MB packuments per scan |
| D-09 | Partial scans | A `partial` scan never resolves findings; a successful scan resolves only finding types whose providers were all requested and OK | DATA_MODEL §6 rule 2 made precise |
| D-10 | Evidence rows | Inserted only when the content hash is new for that finding | Keeps evidence immutable without duplicating it on every rescan |
| D-11 | Semgrep rules | Bundled Apache-2.0 rule set (`toolkit/scanning/rules`) by default; `SEMGREP_RULES=p/default` opt-in | Resolves UD-01 via option (b) and removes the registry network dependency |
| D-12 | Severity without a label | CVSS v3.x vectors are scored with the FIRST formula; v4 vectors stay `null` ("unrated") | Never invent a severity (TRD §5.3) |
| D-13 | Absence rules | `absent_over_time(...[duration])` with N = 1; not evaluated while a target has never reported | The window already encodes the duration; avoids noise for `waiting` targets |
| D-14 | No traffic | Threshold rules on error ratio/latency treat "no traffic" as not breached; `request_rate` treats empty as 0 | Absence rules handle missing data explicitly |
| D-15 | AI model | `CLAUDE_MODEL=claude-sonnet-5-5` (the docs' default), structured JSON-schema output, `effort=medium`, no sampling params, server-side refusal fallback (`fallbacks: "default"`) | Docs name the model; sampling params are rejected by the current API |
| D-16 | Claims with zero checkable facts | `partially_validated`, never `validated` | NFR-AI-01: `validated` requires every check to pass; nothing was checked |
| D-17 | Patch check (VC-07) | `git apply --check` against a fresh hardened clone in the worker | `git apply --check` reads files only; no repository code executes |
| D-18 | Remediation disabled | `POST fix-proposals` / approve return `409 REMEDIATION_DISABLED` | API_SPEC §5.9 is the contract |
| D-19 | Transitive npm fixes | Pinned via `package.json` `overrides` + lockfile-only resolution | `npm install pkg@ver` would wrongly make a transitive dependency direct |
| D-20 | PR delivery | GitHub Git Data API (blobs → tree → commit → new ref) instead of `git push` | No credentials on disk or in a remote URL; creates new refs only, never force-pushes |
| D-21 | Extra endpoints | `POST /alerts/{id}/unacknowledge` (6 s undo), `GET /projects/{id}/summary`, `GET /search`, `GET /projects/{id}/findings/suggestions`, `GET /projects/{id}/timeline`, `GET /ai/status`, `POST /fix-proposals/{id}/retry-pr`; job type `pr_cleanup` | Required by UI_UX_SPEC §9 / Appendix B and the cleanup endpoint's `202` |
| D-22 | PromQL regex escaping | Label values inside `=~"…"` are escaped by `regex_literal()` (RE2 metacharacters only, backslash doubled for the string literal) | Python's `re.escape` escapes `-`, which PromQL rejects; found by the live run (§4) |
| D-23 | Dev dependencies | `[dependency-groups] dev` (installed by plain `uv sync`, excluded by the image's `--no-dev`) | An optional extra would have left CI without pytest |
| D-24 | Visual design | Neutral zinc palette, one indigo accent (separate text and fill shades), Inter, 14 px base, 6/10 px radii, sidebar navigation, data tables instead of cards for lists | Requested redesign: UI_UX_SPEC's coral/periwinkle pill styling read as unprofessional. Information architecture, states and a11y rules from the spec are kept; every text/fill pair checked for WCAG AA in both themes |
| D-25 | Confirmations | Shared promise-based `useConfirm()`; every destructive or hard-to-undo action confirms (archive requires typing the name); frequent reversible actions (acknowledge, dismiss) act immediately with an Undo toast | Confirming everything trains people to click through; undo is better for frequent reversible actions |
| D-26 | Feedback | Every mutation shows a success or error toast with a tone icon | No silent success or failure |
| D-27 | Raw IDs | UUIDs never appear as text: scan filters show the scan time and commit, audit resources show type and name (full ID in a tooltip) | Reported by the user |

**Bugs the live run found (fixed, with regression tests):**

1. Every PromQL query for a service whose name contains `-` failed to parse (`re.escape`), so targets never
   left `waiting` and no rule could be evaluated. Fixed by D-22; test asserts only valid escapes and the fixed
   queries were checked against live Prometheus.
2. A bundled Semgrep rule (`assert-for-validation`) had an unparsable pattern, failing every Semgrep run with
   exit 2; the error text was lost because `--json --quiet` reports errors on stdout. Rule fixed (path
   exclusion), failure reason now read from the JSON, binary-gated test plus a CI step that fails on rule errors.
3. Light-theme accent text on its 15 % tint was 3.9:1 (WCAG AA needs 4.5:1): accent darkened to `#3f49b8`
   (≥ 5.4:1 on every light surface). The profile button's accessible name now contains its visible text
   (WCAG 2.5.3).
4. CI would not have installed pytest (dev tools were an optional extra) — D-23.

## 6. Frontend redesign (2026-10-26, after first review)

User feedback: the UI looked unprofessional, raw IDs appeared, the project list was cluttered on first open,
and the Instrument step was unclear. What changed:

- **Shell:** fixed sidebar (Projects and Admin, plus the open project's Overview, Monitoring, Alerts, Code health
  and Settings with a live alert count), search (Ctrl/⌘ K), account menu with a System/Light/Dark theme switch.
  Mobile uses a top bar and a slide-in drawer. The marketing-style footer was removed.
- **Pages:** projects list as a table; overview leads with four KPI tiles and a severity bar; settings use a
  two-column section layout; monitoring charts gained area fill, hover markers and non-overlapping labels;
  the login page is a two-panel layout with password reveal and a caps-lock hint; the new-project wizard has a
  stepper, and the ingest token is masked on screen (copy still copies the real value).
- **Behaviour:** see D-24 to D-27. Fixed `cn()` (now `tailwind-merge` with the custom tokens), so caller
  overrides such as `p-0` on a card actually apply.
- **Test clutter:** the 18 `e2e-…`/`smoke-…` projects in the local stack came from my test runs. They were
  archived (data kept). The Playwright test now archives its project through the UI (exercising the
  type-to-confirm dialog), and `scripts/smoke_e2e.py` archives its project unless `--keep` is passed.

**Verification:** `tsc`, ESLint clean; Vitest 36 tests (new: confirmation dialog, class merging, job-progress
cancel confirmation); production build; Playwright 5 passed, 1 skipped by design, stable across two repeats,
with axe WCAG 2.1 AA audits on desktop and mobile. Every screen was captured in dark and light themes at
1440 px and 390 px with `web/e2e/screens.spec.ts`, reviewed by eye, and fixed (clipped chart labels,
overlapping p95/p99 labels, a transparent mobile drawer caused by `backdrop-filter`, hyphen spacing from
global tabular figures, label-in-name a11y violations).

**Follow-up:** under parallel E2E load a single Uvicorn process slowed the overview from 0.25 s to 2.5 s.
Running several API workers per container needs Prometheus multiprocess mode for `/metrics` (the `Info`
metric and per-process registries do not aggregate); until then, scale the API with more replicas.
